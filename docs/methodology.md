# Methodology (Phase 1)

Every recommendation is labelled **[Literature]** (published result, cited) or **[Design choice]** (engineering judgment, with reasons), and every item states its **status** in this repo:
*implemented* (file), *config-only* (switchable without code), or *not implemented* (recommended next step). Citations were checked against arXiv/the papers; unverifiable items are marked `[unverified]`.

## 0. Baseline recipe and where this project deviates

**[Literature]** The two reference papers (read in full): *dacl10k: Benchmark for Semantic Bridge Damage Segmentation* (Flotzinger, Rösch, Braml, WACV 2024) and *dacl-challenge: Semantic Segmentation during Visual Bridge Inspections* (Flotzinger et al., WACV 2024 Workshops).
Baseline (Sec. 4.1 of the first paper; the challenge baseline "dacl-squad" = SegFormer MiT-b1 with "all other training parameters unchanged"): DeepLabV3+ and **FPN** decoders with MobileNetV3-Large / EfficientNet-B2 / B4 encoders, plus SegFormer; **512×512** input; one binary mask channel per class (multi-label);
**Dice loss** (+ optional 0.1 × CE auxiliary classification loss); **Adam**, LR swept over {5e-3, 1e-3, 5e-4, 1e-4} (best on val kept); **cosine schedule, 2 warm-up epochs, 30 epochs**; ImageNet init. Best CNN: FPN + EfficientNet-B4 + aux loss, mIoU 0.424 (test) / 0.414 (val); SegFormer 0.400 (val); challenge baseline 0.346 (dev, 10 ep) / 0.372 (final, 30 ep). No augmentation is described in Sec. 4.1.

| element | paper baseline | this project | label |
|---|---|---|---|
| decoder | FPN / DeepLabV3+ | FPN default; `model.decoder: unet\|deeplabv3plus` config | [Literature]-matched |
| encoders | MobileNetV3-L, EffNet-B2/B4 | **MobileNetV3-L** (torchvision), **EffNet-B0** (PROMPT.md asks for B0); SegFormer **MiT-b0** (b1 when task-pretrained) | [Design choice] smaller for 8 GB with three models compared |
| input | 512×512 | 512×512 (config guard refuses < 512) | [Literature]-matched |
| output | 1 binary channel/class | 1 sigmoid channel/class, 5 merged classes | matched; **class set differs → numbers are not comparable to 0.424** |
| loss | Dice (+0.1 aux CE) | per-class focal + Tversky (§5); no aux head | [Design choice], required by PROMPT.md |
| optimizer | Adam | **AdamW**, weight decay 0.01, LR 1e-3 head / 1e-4 backbone | [Literature] Loshchilov & Hutter 2019; [Design choice] values |
| schedule | cosine, 2 warm-up epochs, 30 epochs | same, **plus early stopping** (patience 5) with 30 as a ceiling | [Design choice] anti-overfitting |
| LR | 4-value sweep | single default, sweep by editing config (not automated) | [Design choice] |
| augmentation | none described | flips, rot90, affine, blur, colour jitter, shadow (§4) | [Design choice] anti-overfitting |
| init | ImageNet | ImageNet (`from_scratch`) or task-pretrained (`task_pretrained`): dacl10k-trained MiT-b1 for SegFormer, dacl1k bikit encoders for EfficientNet-B0 and MobileNetV3-Large (see CLAUDE.md) | per PROMPT.md |

Honest scope statement: the *recipe* is reproduced, the *benchmark* is not — the dacl10k paper evaluates 18/19 classes; we train on 5 merged classes from two datasets, so its mIoU cannot be reproduced or directly compared. The comparable statement is per-class behaviour on the merged classes.

## 1. Scale variance (hairline cracks vs. large spalling/wet areas)

Measured on the data (docs/dataset_report.md §4): median instance size at 512 px is ~16–18 px (dacl Spalling/Rust) vs ~146 px (Wetspot). dacl10k crack labels are coarse polygons: median mean-width 24.8 px native -> 7.6 px at 512 (10% of components < 3 px, 27.5% < 5 px, 1.1% vanish), so downscaling loses a thin minority rather than most cracks; cif_coco 'cracks' are mostly regions, not lines.

1. **Multi-scale features** — **[Literature]** FPN (Lin, Dollár, Girshick, He, Hariharan, Belongie, 2017, arXiv:1612.03144), UPerNet (Xiao, Liu, Zhou, Jiang, Sun, ECCV 2018), DeepLabV3+ (Chen, Zhu, Papandreou, Schroff, Adam, ECCV 2018), and SegFormer's hierarchical encoder with All-MLP decoder (Xie, Wang, Yu, Anandkumar, Alvarez, Luo, NeurIPS 2021) all fuse strides 4–32; FPN was the best CNN decoder in the dacl10k paper.
   *Status:* implemented — smp FPN (default) / Unet / DeepLabV3+ (`models/smp_model.py`), SegFormer (`models/segformer_model.py`). UPerNet: not implemented (adding it is one registry entry).
2. **High-resolution branches / resolution** — **[Design choice]** the smp Unet decoder has a full-resolution skip path; FPN and SegFormer predict at 1/4 resolution and upsample, which can smear the thinnest cracks (about a quarter of dacl10k crack components are under 5 px wide at 512). First lever is resolution, not architecture: VRAM headroom exists — measured peak for a full training step (AdamW, AMP, focal+Tversky loss, RTX 3050 8 GB): batch 8 at 512² = 3.15 GB (EffNet-B0), 2.16 GB (MobileNetV3), 2.51 GB (SegFormer-b0); EffNet-B0 at 768² batch 4 = 3.5 GB, at 1024² batch 4 = 6.2 GB / batch 2 = 3.2 GB — so a 768/1024 ablation is affordable. *Status:* config-only (`data.image_size`; default fixed at 512 for baseline comparability, per your decision). Native-resolution training is implemented as `data.resize_mode: native_crop` (`data/datasets/crop_dataset.py`): images are scaled by `data.pixel_scale` (1.0 = native) and the network sees random 512² windows (70% centred on a labelled object, scale jitter), validated on fixed windows and evaluated on a full non-overlapping tile grid; loader throughput ~9x the whole-image path, network cost unchanged. The price is scene context per sample and a much longer evaluation (~40k tiles at scale 1.0). Configs: `effb0_native`, `segformer_native`, `mobilenet_native` (from_scratch) and
   `effb0_task_pretrained_native`, `segformer_task_pretrained_native`, `mobilenet_task_pretrained_native`
   (same bikit checkpoints as the whole_image task-pretrained configs, native_crop resizing instead —
   added 2026-09-24 to directly test whether native_crop helps the models the user actually wants to
   deploy, not just an ImageNet-only ablation).

   **Cross-dataset GSD normalization was investigated and explicitly deferred** (2026-09-24): neither
   cif_coco ("Cracks in the Foundation", arXiv:2605.18413 — real mixed drone/in-the-wild photography,
   not a rendered orthophoto as first, wrongly, hypothesized) nor dacl10k (arXiv:2309.00460 — UAV/
   smartphone/DSLR, zero camera metadata, confirmed by direct EXIF inspection) publishes or permits
   computing an actual ground-sampling-distance. Numbers that looked like GSD (1.05, 3.1) turned out to
   be the CiF paper's own "Resolution (MPx)" column — megapixel counts, not mm/px. `native_crop`'s fix
   above (consistent per-image scale, not tied to native image size) stands on its own regardless;
   absolute cross-dataset physical-scale normalization has nothing to build on and is on hold.
3. **Loss for thin structures** — **[Literature]** clDice (Shit, Paetzold, Sekuboyina, Ezhov, Unger, Zhylka, Pluim, Bauer, Menze, CVPR 2021, arXiv:2003.07311) rewards centreline connectivity; boundary loss (Kervadec, Bouchtiba, Desrosiers, Granger, Dolz, Ben Ayed, MIDL 2019, arXiv:1812.07032) is the contour-distance alternative. Tversky with β > α (§5) biases toward recall on thin classes.
   *Status:* soft-clDice implemented (`losses/boundary.py`), applied to `thin_structure_classes` only, **off by default** (`loss.boundary_weight: 0`): cif_coco's "Cracks" are mostly region-type labels (dataset report §4), where a centreline loss is meaningless, and dacl10k crack labels are coarse. Enable it for a dacl10k-only crack experiment.
4. **Inference-time multi-scale** — **[Literature]** Tao, Sapra, Catanzaro (2020, arXiv:2005.10821, "Hierarchical Multi-Scale Attention for Semantic Segmentation") is the multi-scale inference method the dacl10k paper cites as best on S2DS. **[Design choice]** the cheap version (average probability maps over scales {0.75, 1, 1.25} and flips) is the recommended first step. *Status:* not implemented; `scripts/infer_orthophoto.py --scale` does single-scale GSD normalisation only.

## 2. Class imbalance and rare classes

Reality check (dataset report §2): instance counts are **not** rare — every class has ≥ 6k train instances (partly because cif_coco was already class-balanced by subsampling). The imbalance is in *pixels*: Cracks are 1.8% of dacl10k pixels, Spalling/Rust are small objects, background is the majority in every image.

1. **Per-class binary focal loss on every channel** — **[Literature]** Lin, Goyal, Girshick, He, Dollár (2017, arXiv:1708.02002), designed for the extreme foreground/background imbalance of dense prediction. *Status:* implemented (`losses/focal.py`), per-class α/γ from config.
2. **Tversky / Focal-Tversky** — **[Literature]** Salehi, Erdogmus, Gholipour (2017, arXiv:1706.05721); Abraham & Khan (ISBI 2019, arXiv:1810.07842). *Status:* Tversky implemented (`losses/dice_tversky.py`, α=0.3 FP / β=0.7 FN), combined additively with the focal term. The literal focal exponent — `(1-TverskyIndex)^gamma` as one term, rather than a separate additive focal loss — is now available as an **opt-in** alternative (`loss.focal_tversky_gamma`, default `None` = today's additive form, `losses/combined.py`), added 2026-09-23 as an A/B option rather than a replacement: the additive form's separate focal-BCE term already covers hard-example focusing for the same reason the exponent does, so which is better is an empirical question, not settled here.
3. **Class weighting** — **[Literature]** class-balanced loss via the effective number of samples (Cui, Jia, Lin, Song, Belongie, CVPR 2019). *Status:* not implemented; per-class focal α is the manual equivalent. **[Design choice]** don't add it before looking at per-class val Dice: with ≥ 6k instances/class it is unlikely to be the bottleneck, and the label-semantics issues (§3) matter more.
4. **Class-aware / repeat-factor sampling** — **[Literature]** repeat-factor sampling from the LVIS paper (Gupta, Dollár, Girshick, CVPR 2019, arXiv:1908.03195) oversamples images by the rarity of the rarest class they contain. *Status:* not implemented. **[Design choice]** the first candidate if a class's val recall stays low; images are the sampling unit, so multi-label images are handled naturally.
5. **Copy-paste with COCO instance masks** — **[Literature]** Ghiasi, Cui, Srinivas, Qian, Lin, Cubuk, Le, Zoph (CVPR 2021, arXiv:2012.07177). *Status:* not implemented. **[Design choice]** paste only instances from dacl10k (thin/small object labels); cif_coco's region-type polygons paste implausibly. Pasted pixels should get validity 1 and the paste footprint must also clear other classes' labels only where the semantics say so (rust-in-spalling overlaps must survive).
6. **Few-shot options** — **[Design choice]** not needed for the current five classes. For future classes with < ~100 instances (e.g. glass facades): start from the task-pretrained encoder, freeze it (`training.frozen_epochs`), use copy-paste + heavy augmentation, and evaluate on a fixed held-out set before trusting any number.

## 3. Overly granular taxonomy

**Scheme (implemented)** — **[Design choice]** train on 5 *parent* classes (Cracks, Wetspot, Spalling, Rust, Efflorescence). The merge is a config file per source (`configs/data/label_maps/*.yaml`), reverse-engineered by exact count-matching against your existing remapped data and annotated with BAW MSV-A section numbers.
Reasons: fine children are sparse and partly arbitrary (dacl-challenge paper: Rockpocket vs Cavity "mainly differ in size"; v1 Rockpocket IoU was only 29%), and the Merkblatt itself organises by construction type/process rather than by dacl10k's visual classes.

What does **not** map cleanly (each flagged in the YAMLs and dataset report): Weathering→Wetspot (outnumbers Wetspot 3:1), Algae→Wetspot (proxy label), CrackPrecip→Efflorescence (name misleads), ExposedRebars/Rockpocket/Cavity→Spalling (mixes progressive damage with construction defects), and "Cracks" mixing region-type (cif) and line-type (dacl) labels.

- **Merging strategies** — implemented as above; **[Design choice]** if metrics show a merged class is incoherent, *split it rather than tune losses*: e.g. `Weathering` as its own class or `Cracks` into line/region. Cost is small: edit the label map and `data.mvp_classes`/`model.num_classes` (cross-checked by `configs/schema.py::ExperimentConfig`; `tests/test_config.py::test_adding_a_class_only_needs_config_changes`).
- **Hierarchical outputs (parent + child)** — **[Literature]** Bertinetto, Mueller, Tertikas, Samangooei, Lord (CVPR 2020, arXiv:1912.09393) train with hierarchical cross-entropy/soft labels so that errors stay within a subtree — formulated for single-label *classification*. **[Design choice]** the multi-label segmentation adaptation: keep the 5 parent sigmoid heads as the headline, add optional child heads (channels for ExposedRebars, Cavity, Rockpocket, …) sharing the decoder with a small loss weight, plus a consistency penalty `relu(p_child − p_parent)`. *Status:* not implemented — the dataset currently discards the child identity after mapping; keeping it requires returning a child-level mask channel set.
- **Hierarchical label smoothing / taxonomy-aware losses** — the same paper's soft-label idea; **[Design choice]** not recommended for the MVP: our uncertainty is in *where the mask is*, not *which sibling class*, and smoothing masks blurs the thin-structure signal.
- **Recommended reporting (partly implemented)** — train on parents, report parents (headline). Report *per source* (implemented: `scripts/evaluate.py` writes `source:<name>` rows) so that the two label semantics are never averaged silently. Child-level recall ("what fraction of GT ExposedRebars pixels fall inside the predicted Spalling channel") is a cheap addition once child identity is kept — *not implemented*.

## 4. Domain robustness for orthophotos

Deployment: orthophotos from tiled 3D models, ≈ 2 mm/px nominal but variably sharp, brightness variation, tile seams, no-data regions, vegetation, shadows, boats/ropes/fenders/people.

1. **GSD normalisation** — **[Design choice]** neither source has GSD metadata, so the right rescale factor is an open empirical question `[unverified]`. Training images are downscaled to 512 (×0.5 cif; ≈ ×0.3 typical dacl10k). *Status:* implemented as an inference knob (`infer_orthophoto.py --scale`, probability maps resampled back and re-masked at full resolution). Training-time scale jitter is ±10% (`augmentation.scale_limit`); **widen it to ±30–50% once a labelled orthophoto set fixes the operating scale**. Calibrate `--scale` on labelled orthophoto tiles before trusting outputs.
2. **Blur / degradation matching** — **[Literature]** Zhang, Liang, Van Gool, Timofte (BSRGAN, ICCV 2021, arXiv:2103.14006) argue for a *randomised composition* of blur, resampling, noise and JPEG as a practical degradation model. *Status:* Gaussian blur implemented (σ ∈ [0.4, 2.5], p = 0.3; the σ floor avoids near-identity kernels, a bug seen in a prior project). Down-/up-sampling, JPEG re-encoding, sensor noise and seam-line synthesis are **not implemented** (a sibling project has an `apply_orthophoto_degradation` worth porting).
3. **Brightness / shadows** — implemented: brightness/contrast ±0.2, hue ±5° (small on purpose — Rust and Efflorescence are partly colour-defined), random polygonal shadows (p = 0.2, intensity 0.3–0.7). **[Design choice]**
4. **No-data borders and tile seams** — **[Design choice]**, implemented end-to-end: a validity mask (`data/validity_mask.py`) marks near-black connected regions (≥ 64 px; tolerance 3) invalid; it is excluded from loss (`losses/*`), from all metrics, and zeroes inference output. Measured need: 10.3% of cif_coco train pixels (10.6% val, 10.7% test; measured over all images) are black padding. Geometric augmentation padding (Affine) is also marked invalid. Limits: non-black brightness-step seams are not detected; regions of exact near-black shadow ≥ 64 px would be treated as no-data.
5. **Vegetation, shadows, unwanted objects** — **[Design choice]** the MVP relies on (a) dacl10k's null-mapped classes (Graffiti, objects) as confirmed negatives and (b) 10% pure-negative dacl10k images; there is no explicit "non-structure" class. Recommended next: label a few hundred harbor orthophoto crops (boats, ropes, fenders, vegetation, people) and add them either as **hard negatives** (all-zero targets — already supported) or **ignore regions** (validity 0 — supported by the same mechanism). Adding a dedicated class is a config-only change (§3).

## 5. Losses

`L = w_f · mean_c FL_c + w_d · mean_c (1 − TI_c) [+ w_b · mean_{c ∈ thin} clDice-loss_c]`, all per channel (sigmoid, never softmax), all restricted to valid pixels.
`FL_c` = focal loss with per-class α_c, γ_c averaged over valid pixels; `TI_c` = Tversky index over the split's valid pixels with α = 0.3 (FP), β = 0.7 (FN); `w_f = w_d = 1`, `w_b = 0` by default. Averaging over classes gives every class equal weight in the loss regardless of pixel share. Loss reductions run in float32 under AMP.

- **Why both terms** — focal BCE gives dense, well-conditioned per-pixel gradients and handles the negative-pixel flood; Tversky is a region-overlap loss that is insensitive to class prevalence and, with β > α, favours recall. Their union is the common remedy for tiny foregrounds. **[Design choice]**
- **Validity mask** — invalid pixels contribute zero to TP/FP/FN and to the focal denominator; labels under invalid pixels cannot leak (`tests/test_losses.py::test_invalid_region_labels_do_not_leak_into_loss`).
- **Tuning α/γ per class** — **[Literature]** with γ = 2 the paper found α = 0.25 (weight on positives) best, because focusing already suppresses easy negatives. **[Design choice]** procedure: (i) let per-class thresholds (§6) absorb calibration first — loss weights mainly change ranking quality, not the operating point; (ii) then read per-class precision/recall on val at the chosen threshold: recall ≪ precision → raise α (toward 0.5) and/or Tversky β; precision ≪ recall → lower them; (iii) raise γ (2 → 2.5–3) for classes dominated by easy pixels but poor boundaries. Shipped example: Cracks α = 0.35, γ = 2.5 (thin, rare in pixels). Change one class at a time; `loss.per_class_alpha/gamma` are name-checked against `data.mvp_classes`.
- **Not implemented**: auxiliary classification head (0.1 × CE in the paper), class-balanced weights. Focal-Tversky's exponent is now implemented, as an opt-in (§2 above), not a default.

## 6. Evaluation protocol (implemented in `metrics/evaluation.py`, `scripts/evaluate.py`)

1. **Threshold selection per class on val only** — for each class, sweep thresholds 0.01…0.99 (step 0.02, `metrics/pixel_metrics.py::DEFAULT_THRESHOLD_GRID`; widened 2026-09-23 from an original 0.05…0.95/0.05 grid after two classes' selected thresholds on a finished run landed exactly on that grid's edges) and take the Dice-maximising one (streamed on GPU; ties → lowest). Classes with no val pixels fall back to 0.5. Thresholds are then **frozen** and applied to test; the sweep never sees test. Written to `thresholds.json`. **Checked, not assumed:** re-evaluating the 3 finished checkpoints with the wider grid moved test macro Dice by at most +0.002 and left Rust/Efflorescence's thresholds on `effb0_task_pretrained_cif` exactly where they were (0.05, 0.95) — those edge values are the real optimum, not a grid-truncation artifact, so this fix does not by itself explain those two classes' weaker Dice.
2. **Pixel metrics** (per class): IoU, Dice/F1, precision, recall — accumulated as TP/FP/FN over the *whole* split (exact, not a mean of batch means). Aggregates: **macro** (unweighted mean over classes) and **frequency-weighted** (weights = GT pixel share). Everything inside the validity mask.
3. **Thin structures** — **boundary F1** (2 px tolerance at 512) for every class and **clDice** (hard skeletonisation) for `thin_structure_classes`, averaged over images where the class occurs in GT or prediction (images with the class absent in both are skipped rather than scored 1.0). *Caveat, measured:* clDice on 1–2 px wide structures is sensitive to skeletonisation tie-breaking (a 2 px line shifted by 1 px scored ≈ 0), so interpret it on data where cracks are ≥ 3 px wide; `hard_cl_dice` is unit-tested only for identity/disjoint cases.
4. **Instance level** — GT instances = connected components of the GT class mask; a GT instance is *detected* if some predicted connected component overlaps it at IoU ≥ 0.5; recall reported for **small / medium / large** buckets (area < 32², 32²–96², > 96² px **at evaluation resolution**, not native/mm). One predicted component may be credited to several GT instances, but a prediction merging GT blobs into a much larger region is not credited. **[Design choice]** chosen over COCO mask AP because the model outputs dense maps without instance separation and same-class polygons overlap in dacl10k; *mask AP is not implemented* (PROMPT.md allows either).
5. **Per-source breakdown** — overall, plus `source:cif_coco` / `source:dacl10k` rows, because the two sources have different label semantics and pooled numbers are dominated by whichever contributes more pixels.
6. **Sanity check before trusting anything** — `sanity_check_gt_as_prediction` feeds ground truth back as the prediction through the pixel, boundary and instance code paths and asserts a perfect score; `scripts/evaluate.py` runs it first (skip with `--skip_sanity_check`). Output: `results_{val,test}.csv` + `thresholds.json`. **Transfer to other labelled data:** `--coco/--images[/--label_map]` applies the val-selected thresholds, frozen, to any COCO dataset (`results_<name>.csv`); classes absent from that dataset are excluded from the extra `macro_present` average rather than counted as zero.

## 7. Countermeasures against the overfitting seen in earlier experiments

Root causes found by auditing the sibling projects (not guessed): a staged-unfreezing mechanism that silently never froze anything (`hasattr` on wrong attribute names) and, separately, one that desynchronised the LR scheduler (`optimizer.add_param_group` after scheduler construction); `Adam` with zero weight decay; photometric-only augmentation; no early stopping; tiny/absent val splits (e.g. a 32-image test set, a dataset with no val split); evaluation code that mis-thresholded and deflated AP so training curves were unreliable.
Countermeasures **[Design choice]**, all implemented and tested: AdamW weight decay 0.01 (config refuses 0); early stopping on val macro Dice; geometric + photometric augmentation on train only; both param groups built once, freezing only via `requires_grad` (`tests/test_training_mechanics.py`, incl. a check that freezing really freezes parameters); val split ≥ 694 dacl10k + 1,617 cif images with a *persisted*, disjointness-checked carve; schema validation before epoch 0; train **and** val Dice logged every epoch with explicit `gap/*` metrics to W&B so divergence is visible while it happens.
What these do **not** fix: label-semantics inconsistency across sources (§3) and domain shift to harbor orthophotos (dataset report §5) — a model can generalise well across the val split and still fail on the target domain, which only a labelled orthophoto set can measure.
